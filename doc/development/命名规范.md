# 项目对象命名规范

> 目标：解决各模块实体/传输/接口对象命名混乱（domain 直出 Controller、VO/Response 混用、*Row 语义错位等），按“对象职责定后缀”。

## 1. 对象分类

| 对象类型 | 后缀 | 包 | 允许范围 | 说明 |
|---|---|---|---|---|
| 数据库实体 | `Xxx`（无后缀） | 服务内 `entity` | 仅服务内部 | 与表一一对应（MyBatis-Plus 实体），禁止出 Controller |
| 接口入参 | `XxxRequest` | 服务内 `dto/request` | 服务内 | 如 `UserQueryRequest`、`OrderCreateRequest` |
| 接口出参 | `XxxResponse` | 服务内 `dto/response` | 服务内 | 裁剪/脱敏后返回前端 |
| 跨服务传输 | `XxxDTO` | sca-common `com.example.dto` / dubbo-api | 跨服务 | Redis 缓存载体、RPC 契约 |
| MQ 消息 | `XxxMessage` | sca-common `com.example.dto` | 跨服务 | 如 `PointAddMessage` |
| ES 文档 | `XxxDocument` | 服务内 `es` | 服务内 | 如 `ProductDocument` |
| 转换器 | `XxxConverter` | 服务内 `converter` | 服务内 | Entity ↔ DTO ↔ Response |
| 统一返回 | `Result<T>` | sca-common `com.example.common` | 全局 | 已合规 |

## 2. 关键取舍

1. 出参统一 `XxxResponse`，废弃 `XxxVO`（存量 PointsVO/CreditsVO 迁移为 Response）。
2. DB 实体统一 `entity` 包 + 无后缀类名（`User`/`Order`/`Product`），废弃 `domain` 包名。
3. 跨服务对象统一 `XxxDTO`，放共享模块；task-service 的 `*Row` 属于此类。
4. 入参动词统一：新增/保存用 `Create`，查询用 `Query`。

## 3. 标准包结构（以 user-service 为例）

```
com.example.user
├── controller
├── service / service.impl
├── mapper
├── entity            # User
├── dto
│   ├── request       # UserCreateRequest / UserQueryRequest
│   └── response      # UserResponse
├── converter         # UserConverter
└── mq / cache / ...
```

## 4. 迁移顺序

1. 共享契约：task-service `*Row` → sca-common `UserDTO/OrderDTO/ProductDTO`（Redis JSON 字段不变，兼容）
2. 实体包：`domain` → `entity`（纯移动，类名不变）
3. 出参层：Controller 不直接返回实体，加 `XxxResponse` + `XxxConverter`
4. 收口：统一 Request 动词、Dubbo 返回改 DTO

每一步可独立提交、可回滚，前端 Result 结构保持稳定。

## 5. 强制规则（Service 层与对象转换）

1. **Service 类方法禁止返回 `entity` 包实体**：只能返回 DTO/VO（本项目落为 `dto.response.XxxResponse` 或共享 `XxxDTO`）；实体仅允许在 Service 内部使用（mapper 查询结果、内部流转）。
2. **对象转换统一使用 MapStruct**：`@Mapper(componentModel = "spring")` 接口 + `Mappers.getMapper`，禁止手写 getter/setter 转换。
